\summarybox{%
The maintained browser suite comprises five interfaces for the length-16
doubly-even code catalog and associated Garden representations.  The principal explorer
displays all 145 permutation-equivalence classes of positive-dimensional codes,
their calculated invariants, and a codeword-to-coordinate incidence graph.  A
catalog-wide three-dimensional viewer covers all 145 code classes and 5,128
pairs consisting of a code class and a dashing cohomology class.  A fly-through
viewer presents four selected colored and dashed graphs, and a separate atlas
presents the 512 $k=8$ Garden representations.  A gallery displays all 42
checked-in analytical and graph figures generated by seven programs.  These
products display catalogued
and calculated data.  They do not establish dimensional enhancement or
off-shell supersymmetry.}

\section{Scientific context}

Adinkra chromotopologies arise from quotients of an $N$-cube by doubly-even
binary codes, with dashings and rankings supplying additional representation
data \cite{doran2008topology,doran2008codes,doran2008clifford,doran2012cohomology}.
The 145 catalog entries classify code classes and their associated
chromotopologies.  They are not 145 complete Adinkras, which also require
dashing and ranking data.  The
visualization suite presents the computational catalog used in the current
$N=16$ program, whose physics motivation includes the off-shell
four-dimensional, $\mathcal N=4$ Maxwell problem \cite{arunseangroj2025}.

The visualizations have two purposes:

\begin{enumerate}
  \item make the discrete catalog and its structural invariants inspectable;
  \item present calculated Gadget, spectral, clustering, and graph quantities
        without requiring a reader to reconstruct them from raw arrays.
\end{enumerate}

The visualizations read files produced by the catalog and representation
calculations.  They do not recompute the Garden algebra in the browser.

\section{Primary browser explorer}

The main application is \pathcode{visualizer/index.html}.  It is a static
browser application built with version 7 of the Data-Driven Documents library
\cite{bostock2011} and loads \pathcode{adinkra_codes_n16.json}.  It provides:

\begin{itemize}
  \item filtering by code dimension $k=1,\ldots,8$;
  \item filters for self-duality, self-orthogonality, and indecomposability;
  \item sorting by dimension, minimum distance, codeword count, zero columns,
        automorphism-group size, or catalog index;
  \item an overview scatter plot with selectable vertical metrics;
  \item live summaries of the filtered catalog, including the $k$ distribution,
        decomposability counts, and a zero-column heatmap;
  \item a detail panel for the generator matrix, weight enumerator, column
        profile, minimum distance, automorphism-group size, and structural badges;
  \item a bipartite incidence graph connecting nonzero codewords to the 16
        coordinate positions in their support.
\end{itemize}

The incidence graph visualizes binary-code support.  It is distinct from the
colored and dashed boson-to-fermion Adinkra graph.

\section{Data provenance and validation}

The principal input declares $n=16$ and contains 145 permutation-equivalence
classes of positive-dimensional doubly-even codes \cite{doran2008topology}.  The distribution by code
dimension is

\begin{center}
\begin{tabular}{@{}lrrrrrrrr@{}}
\toprule
$k$ & 1 & 2 & 3 & 4 & 5 & 6 & 7 & 8 \\
\midrule
classes & 4 & 10 & 23 & 38 & 36 & 23 & 9 & 2 \\
\bottomrule
\end{tabular}
\end{center}

Every record supplies the fields consumed by the browser panels: generators,
codewords, weight distribution, column profile, minimum distance,
decomposability, duality properties, zero-column count, and
automorphism-group size.  The catalog contains two self-dual classes and 104
classes marked indecomposable.

The computational backend has tests for code construction, canonicalization,
chromotopology formation, dashing classes, rankings, Garden relations, and
known low-$N$ controls.  The browser views themselves do not have an automated
end-to-end or visual-regression suite.

The catalog exporter writes one compact dashing asset per class.  Its manifest
contains 145 assets and 5,128 dashing classes.  The JavaScript validation
constructs sample topologies from four strata and checks the odd-face condition
for all 256 dashings of catalog class 75.

\section{Reproduction}

Repository:
\href{https://github.com/p1p3dream/adinkra-codespace}{\texttt{github.com/p1p3dream/adinkra-codespace}}.
From the repository root:

\begin{verbatim}
cargo run --release -- export-3d-assets
node scripts/test_adinkra_catalog_3d.mjs
python3 -m http.server 8000
\end{verbatim}

Then open
\href{http://localhost:8000/visualizer/}{\texttt{http://localhost:8000/visualizer/}}.
The catalog-wide three-dimensional viewer is at
\href{http://localhost:8000/visualizer/adinkra_catalog_3d.html}{the catalog 3D viewer}.
The four-example fly-through is at
\href{http://localhost:8000/visualizer/adinkra_interactive.html}{the interactive navigator},
and the $k=8$ interface is at
\href{http://localhost:8000/visualizer/k8_gadget_atlas.html}{the Gadget atlas}.
The checked-in figures are at
\href{http://localhost:8000/visualizer/adinkra_gallery.html}{the figure gallery}.
Serving from the repository root matters because the explorer fetches the
catalog from its parent directory.  The browser pages load the Data-Driven
Documents, Three.js, or Plotly libraries from public content-delivery networks,
so they require network access unless those dependencies are vendored.

The tested command-line pipeline performs the representation calculations and
catalog construction.  The programs under \pathcode{viz/} generate figures.
Separate programs under \pathcode{scripts/} perform exploratory searches and independent
algebraic audits.  The rendering dependencies are pinned in
\pathcode{viz/requirements.txt}.  The script
\pathcode{scripts/generate_all_visualizations.sh} regenerates and validates the
retained visualization products.

\section{Limitations and appropriate use}

\begin{itemize}
  \item The main explorer covers code classes, not every dashing, ranking, or
        supersymmetry transformation matrix.
  \item The catalog three-dimensional viewer supports every class and dashing.
        Its default edge budget limits displayed edges for large low-$k$
        graphs.  Full display remains available.  Dense low-$k$ graphs remain
        difficult to interpret.
  \item The interactive fly-through contains four selected graphs.  It is not a
        second catalog-wide viewer.
  \item The $k=8$ interface displays checked-in results.  It does not calculate
        arbitrary Gadget values in the browser.
  \item Checked-in JavaScript Object Notation files and figures are generated
        artifacts.  The repository provides one command that regenerates the
        catalog assets and all 42 figures, then validates their counts.
  \item None of the views establishes dimensional enhancement, Lorentz
        covariance, closure modulo gauge transformations, or the existence of a
        finite off-shell supermultiplet.
\end{itemize}

The visualizations provide access to data produced by the tested catalog and
representation pipeline.  They are not substitutes for the algebraic verification.
