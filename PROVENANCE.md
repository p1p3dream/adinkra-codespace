# Provenance: 10D Supergravity L & R Dataset (`data/tendim_10d_lr.json`)

This document records the exact origin, regeneration procedure, conventions, and
licensing posture of the 10D L/R matrix dataset shipped in this repository.

The upstream repository contains generative Wolfram Language source, not literal
matrix files. The primary generator is implemented in Rust from the source at a
pinned commit. Rust also verifies all bosonic Garden relations exactly over
`Q(sqrt(2))`. The NumPy and SymPy implementations are retained only as independent
cross-checks. None of these implementations executes Wolfram Language. The basis,
ordering, checks, and paper/source inconsistencies are recorded below.

---

The dataset is generated by transcribing the algebra in the upstream
"Garden Algebra" file into the Rust generator. Its final symbolic values are
verified exactly over `Q(sqrt(2))` before serialization.
It is **not** a copy of a pre-computed dataset published by the authors.

### Canonical content hash (the integrity check that matters)

The raw-byte SHA256 of the JSON is **not** the canonical integrity check, because:

1. Adding/editing metadata fields changes the raw bytes without changing any matrix value.
2. Floating-point formatting and key ordering can drift across serializers.

The canonical check is the **symbolic-token content hash** computed by
`canonical_token_hash()` in `src/tendim_data.rs`. It snaps every L/R entry to its
exact symbolic token (e.g. `-2`, `1/16`, `1/sqrt8`), frames the tokens in a fixed
structural order (matrix index, row, col) under the prefix `TENDIM-TOKENS-v1;`,
and SHA-256s that stream. This hash depends **only** on matrix content, not on
JSON byte layout, so it is stable across reserialization and metadata edits. Use
`canonical_token_hash()` (not the raw-byte SHA256) to verify dataset content.

## 3. Regeneration

The dataset is reproduced deterministically from the pinned upstream source by
running the regeneration script from the repository root:

```sh
cargo run --release -- tendim-generate
cargo run --release -- tendim-reproduce
cargo run --release -- tendim-convention-scan
```

Independent cross-checks:

```sh
python3 scripts/gen_10d_data.py /tmp/tendim-python.json
python3 scripts/eval_garden_exact.py
```

Validated environment: Python 3.12.8, NumPy 1.26.4, SymPy 1.14.0, and
Rust 1.94.1. The Rust generator embeds
`data/tendim_10d_provenance.json`, so a fresh output includes the same metadata
as the committed artifact.

The companion paper (arXiv:2512.12157) was consulted locally; its text was
extracted with `pdftotext` (`pdftotext` output cached at `/tmp/2512_pdf.txt`) to
cross-check degree-of-freedom counts and the worked examples referenced below.

## 4. Conventions

These conventions define the basis in which the matrices are expressed. Two
regenerations agree only if they share these conventions; a different (but
physically equivalent) basis would produce a permuted/sign-flipped dataset.

### 4.1 Colors (generators)

| Convention | Value |
|------------|-------|
| Color index `I` | runs `1 .. 16` |
| Number of generators `n` | 16 |

### 4.2 Boson ordering (`nb = 82`)

| Block | Count | Description |
|-------|-------|-------------|
| Graviton h-pairs (symmetric) | 45 | symmetric `h` components, `{1,1}` pair first |
| `B` field pairs (antisymmetric) | 36 | antisymmetric `B` components |
| Dilaton `Phi` | 1 | single scalar |
| **Total** | **82** | |

DOF derivation (paper Eq. 6.0.3, arXiv:2512.12157, text lines 763-774):
`nb = dof(h_{mu nu}) + dof(B_{mu nu}) + dof(phi) = 55 + 45 + 1 - 19 = 82`,
where the `-19` is the gauge fixing (`h_{0 nu}=0`: 10 components, `B_{0 nu}`: 9 components).

### 4.3 Fermion ordering (`nf = 176`)

| Block | Count | Description |
|-------|-------|-------------|
| Gravitino `psi` | 160 | `psi_{mu, dot a}` |
| Dilatino `chi` | 16 | `chi_a` |
| **Total** | **176** | |

DOF derivation (paper Eq. 6.0.4): `nf = dof(psi_{mu, dot a}) + dof(chi_a) = 160 + 16 = 176`.

### 4.4 Matrix shapes

`L_I` is `nb x nf` (82 x 176); `R_I` is `nf x nb` (176 x 82); 16 of each.

### 4.5 Metric signature

`SO(1,9)` mostly-plus signature `(-,+,+,+,+,+,+,+,+,+)` (one timelike, nine spacelike).

### 4.6 Normalization constants

The Garden Algebra evaluation introduces the following normalization factors:

| Constant | Where it appears |
|----------|------------------|
| `1/2` | sigma-bilinear (`Sig2`/`TildeSig2`) antisymmetrizations |
| `1/8` | R-side entries (token `1/8`) |
| `1/16` | R-side entries (token `1/16`) |
| `1/sqrt8` | dilaton derivative coupling on the R side |
| `sqrt8` | dilatino (`chi`) coupling on the L side (token `sqrt8`) |

### 4.7 Allowed entry value-sets

| Matrix | Allowed exact tokens |
|--------|----------------------|
| `L` | `{ -2, -1, 0, 1, 2, sqrt8 }` |
| `R` | `{ 0, +-1/16, +-1/8, +-7/16, +-1/2, +-1/sqrt8 }` |

### 4.8 Defining relations

| Side | Relation |
|------|----------|
| Bosonic | `L_I R_J + L_J R_I = 2 delta_IJ I_82` |
| Fermionic | `R_I L_J + R_J L_I = 2 delta_IJ I_176 + 2 E_IJ` |

The bosonic Garden relation holds to ~1.7e-12 (computed here). The fermionic
`E_IJ` remnant is **computed here**, not quoted from the paper.

## 5. License and citation posture

The upstream repository `github.com/mcmulaz/Super-Sym` contains **no LICENSE
file** at commit `8c8df92`. There is therefore no granted redistribution license
for any upstream artifact.

This repository does **not** redistribute a licensed upstream dataset. Instead it
ships an **academic regeneration**: the L/R matrices here are produced by
numerically evaluating the authors' own published generative Mathematica
("Garden Algebra"), and the result is provided for scholarly reproducibility with
full attribution to the source and the companion paper.

Anyone using this dataset should cite the source paper:

> arXiv:2512.12157, "10D Supergravity Numerical Data Sets for L & R Matrices",
> with generative code at `github.com/mcmulaz/Super-Sym` (commit `8c8df92`).

If the upstream authors add a license or object to redistribution, this dataset
posture should be revisited.

## 6. Paper/source inconsistency; author intent unresolved

The displayed worked examples disagree with the upstream Garden Algebra output.
The disagreement is established. The authors' intended final normalization is
not established.

The Rust audit checks all 13 displayed transformation equations and all 26 terms.
Four equations and seven terms match directly. The matching equations are the
`phi`, `chi_1`, `chi_9`, and `chi_16` examples.

- Eq. 6.0.5: the six nonscalar examples do not match `L_1`. Several resemble
  `L_11`, but two signs differ, while the scalar line matches `L_1`. Appendix A's
  printed sigma basis gives `Q_1 h_11 = 2 psi_1(16)`, which agrees with the
  generator and disagrees with the displayed `2 psi_1(6)`.
- Eq. 6.0.6: the three graviton coefficients and three dilatino equations match
  `R_1`. Six two-form coefficients do not. For example, the paper gives
  `+1/16 B_19` in `Q_1 psi_1(1)`, while the assembled source gives `-7/16 B_19`.
- A fixed shared permutation of the displayed spinor labels cannot reconcile both
  samples. Eq. 6.0.6 fixes label 16 to 16, while Eq. 6.0.5 would require label 6
  to map to 16. The `chi_9` examples give a separate contradiction. This does not
  exclude a more general physical convention map.

What is established (and IS solid):
- The Rust generator and both independent Python cross-checks agree entrywise with
  zero mismatches. Rust and SymPy each give exact zero bosonic Garden residuals.
- All 136 unordered bosonic color-pair relations close. All 136 corresponding
  fermionic pair matrices have nonzero `E_IJ`; those unordered blocks contain
  132,352 nonzero entries out of 4,212,736 at tolerance `1e-9`. This sparsity is
  basis-dependent.

What is NOT established:
- Which L-row labels and signs the authors intend for the nonscalar Eq. 6.0.5
  examples.
- Which assembled two-form coefficients the authors intend in Eq. 6.0.6.
- Whether the executable `1/16 MixedLeft` coefficient in the Garden source is the
  intended three-form normalization. A nearby source comment says `1/8`, while
  the executable expression uses `1/16`. A complete Rust variant using `1/8`
  fails all 136 bosonic Garden pair relations at 7,296 scalar entries and does
  not improve the printed-example matches. Thus `1/8` is not a consistent
  alternative when all other executable formulas are held fixed.

**Status:** the Rust generator and two independent cross-checks agree entrywise; the paper/source
inconsistencies are documented; the intended matrices require author confirmation.
No correction to the paper or source is asserted.

## 7. What is and is not claimed

- **Claimed:** the dataset is a deterministic 12-decimal serialization from a
  transcription of the upstream "Garden Algebra" code at the pinned commit; an
  independent exact-arithmetic transcription agrees entrywise; the bosonic Garden relation holds
  to ~1.7e-12; all entries snap to the documented exact token value-sets; the DOF
  counts match the paper (Eq. 6.0.3-6.0.4).
- **Not claimed:** that the dataset is byte-faithful to any matrices the authors
  published, or that it reproduces every worked example in the paper (see the
  known mismatch in section 6).

The validation checks the complete vertex and edge sets, all 21 published `S4`
correlator blocks, the 5,040 right and left `R8` cosets, the 168 coincident
left-right slices, the 30 conjugate `R8` subgroups, all 40,320 intra-coset

graph distances and are not holoraumy gadgets.

The full `S8` all-pairs distance matrix is not stored. The two-point distance is
computed from the one-line addresses when requested. The atlas does not solve
general sign assignment or construct a supersymmetric field equation.
